# Binary Distribution Archives & Release Pipeline Design

**Date:** 2026-11-07
**Status:** Approved
**Scope:** Multi-language binary packaging and automated tag-triggered publishing for **npm** (`lavi-fsm`), **crates.io** (`lavi`), **PyPI** (`lavi`), and **Maven Central** (`io.github.emmby:lavi`).

---

## 1. Intent & Why

`lavi` is a portable XState v5 statechart runtime written in `#![no_std]` Rust with bindings for JavaScript/TypeScript (WASM), Python (`PyO3`), and Java/Kotlin (`JNI`), plus C/C++. Today, building any target requires a local Rust toolchain (`cargo`, `wasm-pack`, `maturin`, `gradle`).

To provide a smooth, idiomatic developer experience across ecosystems, consumers in non-Rust languages must be able to install pre-compiled binary packages from their native package registries without having `rustc` or `cargo` installed, and releases across all registries must be built and published deterministically from a single `v*` git tag push in GitHub Actions.

---

## 2. Goals, Non-Goals & Anti-Goals

### Goals
1. **npm (`lavi-fsm`)**: Package a unified npm tarball containing `--target nodejs`, `--target bundler`, and `--target web` WASM builds with conditional `exports` in `package.json` (resolving `TD-12`), so `npm install lavi-fsm` works in Node.js, Vite/Webpack/Rollup/esbuild bundlers, and raw browser ES modules.
2. **crates.io (`lavi`)**: Prepare [`lavi/Cargo.toml`](../../../lavi/Cargo.toml) with complete registry metadata (`readme`, `keywords`, `categories`, `documentation`, `homepage`) and verify `cargo publish --dry-run -p lavi`.
3. **PyPI (`lavi`)**: Package `cp39-abi3` binary wheels (`.whl`) across Linux (`x86_64` & `aarch64` `manylinux` and `musllinux`), macOS (`x86_64` & `arm64`), and Windows (`x86_64`), plus a source distribution (`sdist`), so `pip install lavi` / `uv add lavi` installs pre-built binaries across Python 3.9–3.13+.
4. **Maven Central (`io.github.emmby:lavi`)**: Configure [`lavi-jvm/build.gradle.kts`](../../../lavi-jvm/build.gradle.kts) with `group = "io.github.emmby"` and artifact ID `lavi` (keeping Java/Kotlin classes in `package io.lavi`), bundling desktop JNI libraries under `/native/<target>/` inside the main `.jar`, generating `-sources.jar` and `-javadoc.jar`, signing with PGP, and publishing via Sonatype Central Portal (`maven-publish` + `signing` + Central Portal bundle upload). Also attach the 16 KB page-aligned Android `.aar` (`lavi-release.aar`) to GitHub Releases.
5. **Version Synchronization & Tag Verification**: Provide a script (`scripts/sync-version.mjs`) that synchronizes or validates versions across `Cargo.toml` (`lavi`, `lavi-wasm`, `lavi-py`, `lavi-jvm`, `lavi-c-cpp`), `package.json`, `lavi-py/pyproject.toml`, `lavi-jvm/build.gradle.kts`, and `library.json`, failing CI release builds if a `vX.Y.Z` tag does not match the manifest versions.
6. **GitHub Actions Release Workflow (`.github/workflows/release.yml`)**: Trigger on `push.tags: ['v*']` and `workflow_dispatch` (with a `dry_run` boolean input), building all artifacts, attaching them to the GitHub Release, and publishing to npm, crates.io, PyPI, and Maven Central when not in dry-run mode.

### Non-Goals (Deferred)
- **PlatformIO Registry & Arduino IDE Library Manager**: Explicitly deferred until the Arduino IDE pre-compiled archive strategy is designed.
- **vcpkg / Conan Center / Homebrew**: Deferred to a future C/C++ desktop distribution track.

### Anti-Goals (What Would Make This a Failure)
- Requiring JS, Python, or Java/Kotlin consumers to install `rustc`, `cargo`, `wasm-pack`, or C compilers to install `lavi`.
- Breaking existing local repo test paths (`lavi-wasm/pkg-npm/lavi.js` and `lavi-wasm/pkg/lavi.js` used by `vitest`, `playwright`, and `examples/`).
- Modifying any upstream conformance test files in `tests/*.test.ts` or `tests/upstream/` (Level 1 invariant in [`AGENTS.md`](../../../AGENTS.md)).

## 3. Target-by-Target Packaging Specification

### 3.1 npm (`lavi-fsm`) — Decided by User (`lavi-fsm` package name) & Builder Calls

- **Package Name**: `lavi-fsm` (unscoped `lavi` is already occupied on npm).
- **Local Test Path Compatibility (Builder Call)**: Keep `npm run build:npm` producing `lavi-wasm/pkg-npm` and `npm run build:web` producing `lavi-wasm/pkg` so all existing Vitest conformance tests (`../lavi-wasm/pkg-npm/lavi`) and Playwright HTML tests (`../lavi-wasm/pkg/lavi.js`) continue working untouched.
- **Unified Distribution Directory (`dist/npm/` via `scripts/build-npm-package.mjs` — Builder Call)**:
  - Run `wasm-pack build` for three targets:
    1. `--target nodejs --out-dir dist/npm/node --out-name lavi`
    2. `--target bundler --out-dir dist/npm/bundler --out-name lavi`
    3. `--target web --out-dir dist/npm/web --out-name lavi`
  - Strip `.gitignore` and nested `package.json` files generated by `wasm-pack` inside `node/`, `bundler/`, and `web/`.
  - Generate `dist/npm/package.json`:
    ```json
    {
      "name": "lavi-fsm",
      "version": "<version>",
      "description": "Portable XState v5 statechart runtime powered by Rust and WebAssembly.",
      "license": "MIT",
      "repository": {
        "type": "git",
        "url": "git+https://github.com/emmby/lavi.git",
        "directory": "lavi-wasm"
      },
      "homepage": "https://emmby.github.io/lavi/examples/",
      "keywords": ["xstate", "statechart", "state-machine", "fsm", "wasm", "lavi"],
      "files": [
        "node/",
        "bundler/",
        "web/",
        "README.md",
        "LICENSE"
      ],
      "main": "./node/lavi.js",
      "module": "./bundler/lavi.js",
      "types": "./node/lavi.d.ts",
      "exports": {
        ".": {
          "types": "./node/lavi.d.ts",
          "node": "./node/lavi.js",
          "browser": "./bundler/lavi.js",
          "import": "./bundler/lavi.js",
          "default": "./node/lavi.js"
        },
        "./web": {
          "types": "./web/lavi.d.ts",
          "import": "./web/lavi.js",
          "default": "./web/lavi.js"
        },
        "./package.json": "./package.json"
      }
    }
    ```
  - Copy [`LICENSE`](../../../LICENSE) and [`lavi-wasm/README.md`](../../../lavi-wasm/README.md) (updated to reference `lavi-fsm`) into `dist/npm/`.

### 3.2 crates.io (`lavi`) — Decided by User (`lavi` crate name)

- **Crate Name**: `lavi`
- **Manifest Updates ([`lavi/Cargo.toml`](../../../lavi/Cargo.toml))**:
  - Add `readme = "../README.md"` (or copy `README.md` into `lavi/README.md` so cargo packages it cleanly without workspace-relative path issues), `homepage = "https://emmby.github.io/lavi/examples/"`, `documentation = "https://docs.rs/lavi"`, `keywords = ["statechart", "xstate", "fsm", "state-machine", "no-std"]`, `categories = ["no-std", "embedded", "simulation", "algorithms"]`.
  - Add `include = ["src/**/*", "Cargo.toml", "README.md", "LICENSE"]`.
- **Verification**: `cargo publish --dry-run -p lavi` must succeed cleanly.

### 3.3 PyPI (`lavi`) — Decided by User (`lavi` package name)

- **Package Name**: `lavi`
- **Build System**: `maturin` (`>=1.5,<2.0`) configured in [`lavi-py/pyproject.toml`](../../../lavi-py/pyproject.toml) with `pyo3` `abi3-py39` in [`lavi-py/Cargo.toml`](../../../lavi-py/Cargo.toml).
- **Metadata Updates ([`lavi-py/pyproject.toml`](../../../lavi-py/pyproject.toml))**:
  - Ensure `version` matches the workspace release version (`0.1.0` / synced via `scripts/sync-version.mjs`).
  - Add `[project.urls]` (`Homepage`, `Repository`, `Issues`) and ensure `lavi-py/README.md` and `LICENSE` exist so `maturin sdist` and `maturin build` include complete project documentation on PyPI.
- **Wheel Matrix (Builder Call)**:
  - Build `cp39-abi3` wheels for the 7 desktop targets already defined in [`scripts/build-release-natives.mjs`](../../../scripts/build-release-natives.mjs) (`aarch64-apple-darwin`, `x86_64-apple-darwin`, `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu`, `x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl`, `x86_64-pc-windows-gnu`) plus `sdist` (`lavi-<version>.tar.gz`).

### 3.4 Maven Central (`io.github.emmby:lavi`) — Decided by User (`io.github.emmby` groupId)

- **Coordinates**:
  - `groupId`: `io.github.emmby`
  - `artifactId`: `lavi`
  - Java/Kotlin package namespace inside the JAR remains `io.lavi` (`import io.lavi.Machine`, `import io.lavi.SimulatedClock`).
- **Bundled Native Binaries**:
  - [`NativeLoader.java`](../../../lavi-jvm/src/main/java/io/lavi/NativeLoader.java) extracts from `/native/<target>/<libName>` where `<target>` is `darwin-aarch64`, `darwin-x86_64`, `linux-x86_64-gnu`, `linux-aarch64-gnu`, `linux-x86_64-musl`, `linux-aarch64-musl`, and `windows-x86_64`.
  - Before running `./gradlew :packageMavenCentralBundle` (or `publishToMavenLocal`), all 7 compiled JNI shared libraries are staged into `lavi-jvm/src/main/resources/native/<jvmFolder>/<libName>`.
- **Gradle Publishing & Signing ([`lavi-jvm/build.gradle.kts`](../../../lavi-jvm/build.gradle.kts) — Builder Call)**:
  - Enable `withSourcesJar()` and `withJavadocJar()` in the `java` block.
  - Apply `maven-publish` and `signing` plugins.
  - Configure `publishing.publications.create<MavenPublication>("mavenJava")` with `groupId = "io.github.emmby"`, `artifactId = "lavi"`, and full Sonatype-required POM metadata (`name`, `description`, `url`, MIT `licenses`, `developers`, `scm`).
  - Configure in-memory PGP signing (`useInMemoryPgpKeys(System.getenv("MAVEN_GPG_PRIVATE_KEY"), System.getenv("MAVEN_GPG_PASSPHRASE"))`) gated on `System.getenv("MAVEN_GPG_PRIVATE_KEY") != null` so local builds and tests succeed without GPG keys.
  - Add a staging repository (`layout.buildDirectory.dir("staging-deploy")`) and a `zipMavenCentralBundle` Zip task that generates checksums (`.md5`, `.sha1`, `.sha256`, `.sha512`) and packages `io/github/emmby/lavi/<version>/*` into `dist/maven/lavi-maven-central-bundle.zip` ready for Sonatype Central Portal's `/api/v1/publisher/upload` API (or local inspection).

## 4. Release Automation & Version Sync

### 4.1 Version Synchronization (`scripts/sync-version.mjs` — Builder Call)
- CLI usage:
  - `node scripts/sync-version.mjs --check [expectedVersion]`: Verifies that `lavi/Cargo.toml`, `lavi-wasm/Cargo.toml`, `lavi-py/Cargo.toml`, `lavi-jvm/Cargo.toml`, `lavi-c-cpp/Cargo.toml`, `lavi-py/pyproject.toml`, `lavi-jvm/build.gradle.kts`, `library.json`, and `package.json` all share the exact same version (and match `expectedVersion` if passed, e.g. from `GITHUB_REF_NAME` stripped of leading `v`).
  - `node scripts/sync-version.mjs <newVersion>`: Updates all manifests atomically to `<newVersion>`.

### 4.2 GitHub Actions Release Pipeline (`.github/workflows/release.yml` — Decided by User)
- **Triggers**:
  - `push: tags: ['v*']`
  - `workflow_dispatch` with input `dry_run: boolean (default: true)`
- **Jobs**:
  1. **`verify`**: Runs `node scripts/sync-version.mjs --check` against the tag version and runs the test suite (`npm test`).
  2. **`build-wasm-npm`**: Builds the unified `lavi-fsm` npm package (`node scripts/build-npm-package.mjs`), verifies the packed tarball contents and Node/bundler/web entrypoints, and uploads `dist/npm` + `lavi-fsm-<version>.tgz` artifact.
  3. **`build-natives-py-jvm`**: Uses `zig` (`cargo-zigbuild`), `maturin`, and Android NDK (`cargo-ndk`) via `node scripts/build-release-natives.mjs --execute` to cross-compile the 7 desktop targets (for both `lavi-py` wheels and `lavi-jvm` JNI libraries) + `maturin sdist` + 3 Android ABIs (`lavi-release.aar`), then packages the Maven Central bundle (`./lavi-jvm/gradlew -p lavi-jvm zipMavenCentralBundle`). Uploads wheels, sdist, Maven Central bundle, and Android AAR as workflow artifacts.
  4. **`publish`** (runs after `verify`, `build-wasm-npm`, `build-natives-py-jvm`; publish steps skipped when `dry_run == true`):
     - Creates/updates the **GitHub Release** with all binary archives (`.tgz`, `.whl`, `.tar.gz`, `.jar`, `.aar`, `lavi-maven-central-bundle.zip`).
     - Publishes `lavi` to **crates.io** (`CARGO_REGISTRY_TOKEN`).
     - Publishes `lavi-fsm` to **npm** (`NPM_TOKEN` / npm provenance).
     - Publishes `lavi` wheels + sdist to **PyPI** (PyPI Trusted Publishing OIDC via `pypa/gh-action-pypi-publish`).
     - Uploads `lavi-maven-central-bundle.zip` to **Sonatype Central Portal** (`MAVEN_CENTRAL_USERNAME` + `MAVEN_CENTRAL_TOKEN`).
     - All four registries are required when `dry_run == false` (no silent skip-if-unconfigured fallback).

### 4.3 Registry Setup Guide & GPG Helper (`RELEASING.md` & `scripts/setup-maven-gpg.sh`)
- Create `RELEASING.md` documenting one-time account/OIDC/secret setup across crates.io, PyPI, npm, and Sonatype Central Portal, plus how to cut a release (`node scripts/sync-version.mjs <X.Y.Z>` + `git tag v<X.Y.Z>` + `git push origin main --tags`).
- Create `scripts/setup-maven-gpg.sh` to generate a PGP signing keypair, publish the public key to `keys.openpgp.org` and `keyserver.ubuntu.com`, and export the armored private key for `MAVEN_GPG_PRIVATE_KEY`.
